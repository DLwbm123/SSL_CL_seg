## Source and comparability audit

The legacy `lcrseg.engine.continual_runner.ContinualRunner` already implements both arms with the same optimizer, loader, transforms, evaluator and checkpoint machinery. Its Sequential-SSL pseudo targets come from the **current student**, not an EMA teacher. Its supervised loss is CE plus foreground soft Dice; the model has a deterministic 1x1 segmentation head. Existing Uniform-KD adds old-weak to current-strong output distillation and uses temperature 0.5 by default. Its inherited constructor incorrectly records `sequential_ssl` as the runtime/checkpoint method name. Correct this identity defect before new execution; do not rewrite or resume historical mislabeled checkpoints. The observed defect concerns provenance and resume identification, and does not by itself establish wrong historical gradients.

Clean B0 v3 instead uses the repaired Gate0 runner, a stochastic 3x3 classifier, supervised CE, PAS probability MSE, GAS/EMA, 100 epochs/domain and 5,295 logged steps/seed. Its published Dice is pooled from confusion matrices. The legacy full protocol uses 200 epochs/domain, 13,400 steps and patient/case-mean Dice. Historical seed-0 legacy scores are validation-only. They cannot be pooled with B0 test scores or used as this study's paired control. All six new arms are trained anew. Neither repaired Gate0 code nor its frozen validator is changed to accommodate this comparison.

[Li and Hoiem's paper](https://arxiv.org/html/1606.09282v3), section III, uses recorded old-network responses on new-task inputs, T=2 and usually old-loss weight 1. Its experiments are task-incremental image classification with expanded heads. The [author repository](https://github.com/lizhitwo/LearningWithoutForgetting/tree/795176d49017663ae76455e6536b4c2b7caf35fe) is a MatConvNet implementation (resolved release commit `795176d49017663ae76455e6536b4c2b7caf35fe`; README blob `db2fb6d1e98fc1593f642c70d57c7c4d014ca2b8`). This study reuses the project's own uniform-KD implementation; no author code is copied. It is explicitly an **LwF-style fixed-class segmentation adaptation**, not a faithful reproduction of the paper's architecture, warm-up, objective coefficient or reported results. Its T-squared scaling, SSL term, strong views and ramp are adaptation choices frozen below, not paper settings.

[DC2T's institutional publication record](https://research.cuhk.edu.hk/en/publications/dct-disentanglement-guided-consolidation-and-consistency-training/) establishes relevant semi-supervised cross-site Fundus work, but this audit has not verified an author implementation or complete executable contract. Do not infer equations from the abstract or label our baseline DC2T. The [JASCL baseline catalogue](https://github.com/prinshul/JASCL/blob/3c93ca70784fc3a1d2a887f8d7dce5af6bc75f53/baselines.md) covers several different incremental task definitions; a listed method is not automatically a compatible Fundus control.

## Fixed question, arms and training

Question: under one matched legacy weak/strong SSL framework, does fixed uniform output distillation improve retention and final Fundus segmentation across three seeds? This does not test improvement over repaired B0 or establish a novel method.

- S0: `sequential_ssl`.
- S1: `uniform_kd`, T=2, coefficient=1.0, with the existing T-squared-scaled pixel KL and 1,000-step linear ramp. No grid or alternate coefficient/temperature.
- Seeds 0, 1, 2 use their respective frozen splits and the same optimization seed within each paired arm. Initialization and input ordering are paired. No historical checkpoint initialization.
- Domain order: REFUGE -> RIM_ONE_r3 -> Drishti_GS; fixed 20% visible-label training view. Counts per seed are respectively labeled/unlabeled/val/test = 40/160/100/100, 16/63/40/40, 10/41/25/25.
- Shared unchanged UNet2D 16/32/64/128, GroupNorm, deterministic 1x1 head. The existing projection output remains unused by both losses; no prototype, anchor, relation loss or memory is created.
- Supervised objective: CE + 1.0 foreground soft Dice. SSL: current weak-view student argmax, confidence >= 0.95, detached hard-label CE on the strong view, valid cutout mask, coefficient 1.0 and 1,000-step ramp reset per domain.
- S1 additionally distills the frozen previous domain's **final student**, with no gradients or updates, on current unlabeled inputs only. No old images or old labels are retained or read for training. Old weak/current strong views have identical geometry; KD averages all non-cutout pixels without class/confidence filtering. No third/EMA teacher.
- Adam lr=0.0005, weight decay=0.00001; cosine schedule reset each domain. Batch sizes labeled=2, unlabeled=4; 200 epochs/domain. No gradient clipping. FP32 (`amp=false`) in both arms; this differs from historical AMP scores and is not a historical rerun claim. Deterministic cuDNN and CUBLAS settings; unsupported deterministic operations warn, and numerical resume checks use atol=rtol=1e-6.
- Existing weak/strong augmentation: independent horizontal/vertical flips p=0.5 shared between views; strong Gaussian noise std=0.03, brightness/contrast deltas=0.10; cutout p=0.5, side fraction=0.20. Labeled flips p=0.5. No resizing or generated data; read the frozen stored HDF5 geometry.
- Budget: 8,000 + 3,200 + 2,200 = **13,400 steps per arm/seed; six runs, 80,400 formal optimizer updates maximum**. No AMP skips; nonfinite values or any incomplete budget fail engineering acceptance. Save latest every 500 steps and final each domain, without interval history copies. At most three simultaneous workers, each on one allowed GPU; all outputs/cache/scratch on a new NAS directory. At most 12 hours per formal worker invocation; at most two infrastructure-only resumes per run from a verified latest checkpoint, never a new attempt or changed configuration. SSH observation loss alone does not trigger resume.

## Evaluation and prospective success rule

No checkpoint selection: train the fixed full budget and retain each domain's final model. The shared runner writes validation metrics on all three domains at each stage; these are descriptive and never change the schedule, model or hyperparameters. No test access is allowed during engineering checks or formal training. After **all six runs finish and pass provenance/budget/input-immutability checks**, a separate evaluator reads each final-stage checkpoint once per seen test domain, yielding the complete six-cell lower-triangular test matrix for each run. No extra test retries, data selection, threshold adjustment or candidate selection. Private case-level tables and predictions stay on NAS; public tables contain aggregate scores only.

Use the existing evaluator's classwise hard Dice, with empty/empty Dice=1, averaged first over foreground classes 1/2 per patient, then patients per domain. This differs from pooled B0 metrics. For seed s and arm a, define F = mean of three final-row domain Dice, I = mean of three diagonal Dice, BWT = mean of final-minus-diagonal Dice for the first two domains. Pair S1-S0 within seed. All three paired seeds, all 36 required test cells and both foreground classes must be finite and present.

The fixed **baseline feasibility** gate requires all: mean delta F >= 0.01; delta F > 0 in at least 2/3 seeds; every delta F >= -0.01; mean delta BWT >= 0.01; mean delta I >= -0.01. These are operational one-Dice-point margins, not claims of clinical significance. Publish every per-seed result and failed condition. No significance claim from three seeds. Passing supports a subsequent separately registered comparison; it does not establish a novel method, superiority over B0, independent peer review, or overall project success.

Failure labels: `FAIL_ENGINEERING` for incomplete/corrupt/nonfinite/mismatched evidence; `FAIL_BASELINE_FEASIBILITY` for any scientific bound failure after otherwise valid completion; `PASS_BASELINE_FEASIBILITY` only when every bound passes. Engineering failure never becomes a negative scientific result. No changing the gate after seeing results and no rescue arm. Retain all unsuccessful runs.

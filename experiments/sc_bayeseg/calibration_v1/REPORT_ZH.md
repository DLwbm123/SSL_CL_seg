# SC-BayeSeg 改进分析与生成后验预校准验证报告

## 结论

当前最值得优先验证的改进是**先冻结已拟合的推断器、校准生成参数后验，再解冻联合优化**。它只改变优化顺序，保留原概率模型、完整ELBO及Adam历史，能够直接检验“生成器尚未匹配监督表示便开始联合更新”的解释。

本轮已按这一方向实现并启动，但在工程资格检查中发现了我新增诊断代码的随机状态隔离错误，实际消耗 **2次工程优化更新、0次正式更新**，随后停止。尚未得到K校准或T联合训练结果，不能声称改进有效或无效。修复通过零更新复核，未自动重跑；半小时监测已设置，因本次有成本失败而暂停。

## 一、为什么先改优化顺序

上一轮已有的对照证据见[联合目标报告](../jointwrite_v1/REPORT_ZH.md)：

| 路径 | 两张训练图三类前景平均Dice | 说明 |
|---|---:|---|
| 共同L3起点 | 96.2809% | 已有监督语义 |
| 随机CE继续600步C | 98.5494% | 随机proposal本身能维持并提高拟合 |
| 完整ELBO联合600步J | 0% | 25步已有明显破坏，100步全部前景Dice为0 |

这些是两个训练样本的拟合指标，不是泛化成绩。它们说明当前网络与随机CE链具备基本拟合能力，而直接进入完整联合目标会破坏已学语义。尚不能将这一现象等同于概率模型必然无效。

本轮新增的零更新、8次共同随机数分项读数如下，单位均为每像素负对数密度或负熵贡献的MC均值：

| 项 | 起点读数 |
|---|---:|
| 图像重建负对数密度 | 12.27859 |
| 结构条件负对数密度 | 3.88294 |
| logits条件负对数密度 | 28.07035 |
| 标签CE | 0.0065584 |
| 局部log q贡献 | 17.79299 |
| 全局KL | 0 |
| 完整负ELBO | 63.28229 |

另有code和appearance项，详见[分项结果](results/DENSITY_INITIAL.json)。密度可以为正，分项负值也不自动意味着数学错误；数值大小不等于梯度大小。

CE约束分类概率，并不要求监督学习得到的x、c及logits尺度适合随机初始化的生成分布。已有J中，x RMS从约6.22降至约0.79，语义同时消失；图像及logits项改善远大于标签项恶化。这支持表示与生成约束不匹配、共同更新存在优化冲突的解释。

尤其是，**仅校准Θ能够改变F(P)、G(c)，却不能改变I−x−m残差**。因此，即使生成条件拟合得到改善，解冻后图像项仍可能推动x大幅变化。新验证必须同时记录这部分，不能把“生成器校准”视为必然修复。

## 二、这次固定的验证设计

完整方案见[预注册协议](PREREG_ZH.md)。

- 共同起点：L3第1800步完整model、Adam、scheduler、RNG；保留原先验。
- K：全部推断器φ冻结，仅生成参数后验Θ优化600步。
- T：继承K终态，解冻全部参数，完整联合目标600步。
- 同两张Siemens可见L，NL=2、NU=0；不加无标注数据、不扩目标域、不增加种子。
- 原模型、原损失、原概率尺度；lr=3e-4、FP32、clip1，不调参。
- 每阶段两次完整状态golden更新，原计划正式1200、工程最多4，总上限1204。
- K/T终态分别做固定φ0的生成后验置换诊断，训练2图和另2患者可见L留出图分开报告，不用标签似然给候选评分。

冻结期间原φ的Adam历史不清零、不推进；T恢复更新后再继续其step。Θ在K建立历史并传给T。正常情况下，这能将优化顺序与额外监督损失、后验先验重置、推断器重新拟合等变化分开。

历史J可作为失败形态参考，但本轮多出600步生成校准且随机流不同，不能把差异解释为严格等预算配对因果效应。

## 四、失败原因：新增诊断的RNG隔离错误

新增density函数为了配对MC诊断调用seed_everything，它会同时设置Python、NumPy和Torch随机状态。原实现只保存并恢复Torch CPU/CUDA状态，遗漏Python和NumPy。

执行顺序恰为：保存工程起点 → 分项密度诊断 → 第一次golden更新 → 恢复工程起点 → 第二次golden更新。因此两次更新后的完整快照至少在Python/NumPy RNG上不同，完整状态断言必然无法通过。

零更新复核的结果：

| 检查 | 原density | 修复density |
|---|---|---|
| 保持Python RNG | 否 | 是 |
| 保持NumPy RNG | 否 | 是 |
| 保持Torch CPU RNG | 是 | 是 |
| 保持Torch CUDA RNG | 是 | 是 |
| 两版本密度数值 | 相同 | 相同 |

采用“原诊断后的完整RNG”与“原工程起点RNG”分别做一次纯前向，损失均为63.4316635；Torch后续状态相同，Python/NumPy仍不同。这是直接的工程错误证据，**不是ELBO发散或概率模型失效证据**。

原第一次golden完整快照未落盘，所以无法事后证明当时两次更新的model和Adam逐项全部相同。本报告不将前向相同扩大为完整优化轨迹相同，也没有通过重做优化来填补这个证据缺口。

修复内容：

1. density改用项目已有的完整capture_rng_state/restore_rng_state。
2. 为已有评价helper加完整RNG隔离，避免同类评估副作用。
3. 后续工程比较先写loss/model/trainer及逐类RNG比较回执，再执行断言，保留更明确的失败证据。
4. 增加零反向、零optimizer调用的RNG隔离回归检查。

真实数据的零更新复核使用46图像级proposal、36图像级density调用、18次Θ抽样，没有反向或更新；公开的小型回归检查也通过。另一次只读诊断入口曾因文件名与标准库inspect冲突而在导入前失败，改名后完成，优化成本为0。详见[RNG诊断](results/RNG_DIAGNOSIS.json)及[回归检查](checks.py)。

**本轮实际运行代码为提交685d8dd；交付的修复代码未再次启动训练，不应把修复后的源码误认为本轮已验证通过的训练版本。**

## 五、如何据此改进方法

### 第一优先：先把优化顺序这个解释验证完

当前最小路线仍是预注册的K→T。修复的是工程隔离，不是科学配置；但这次已经产生真实成本，按用户要求不能自动重跑。剩余预算也不能视为一个新的1204步授权：已消耗2步必须保留，若重新做完整资格检查，需要先明确累计预算和执行授权。

若之后获准完成验证，应依据以下读数组合判断：

| 观察 | 能支持的解释 | 仍不能声称 |
|---|---|---|
| K降低shape/logits NLL，T保住语义 | 生成条件失配及更新顺序是可修复因素 | SSL/持续学习有效 |
| K降低条件NLL，T仍塌缩 | 这600步Θ校准不足以解决联合冲突；继续定位图像残差和φ更新 | 所有坐标优化都无效 |
| K条件NLL几乎不变 | 固定表示下生成器拟合/参数化或优化仍受限 | 确定是哪一种原因 |
| T保持Dice，但留出空间边际仍差 | 语义可能主要仍在推断器 | Θ已形成可靠可迁移语义 |
| 训练及留出空间边际均改善 | 更有理由继续检验后验语义 | 小样本诊断已证明泛化或遗忘控制 |

### 若优化顺序仍失败，再考虑概率参数化

当前结构的关键风险是：监督分类能利用x的任意数值表征，而生成侧又把同一个x解释为与图像相加的物理强度结构。**分类表征的自由度与生成变量的含义并不自动一致。** 这比简单增加前景权重更值得优先处理。

一种后续建模方向是明确区分服务分类的特征与具有强度语义的生成变量，或重新约束结构/外观的可识别性；但这会改变模型，必须另立最小对照，不能在本轮作为“工程修复”偷偷加入。额外CE权重、Dice损失、阈值筛选或过采样可能改善表面拟合，却会同时改变统计目标或采样解释，现阶段不宜用它们掩盖联合目标的问题。

同样，当前源域联合语义尚未通过，暂时加入U或跨域后验递推只会叠加原因。先证明“完整联合目标保留监督语义，并使生成后验获得可调用的结构信息”，再讨论principled SSL-CL的持续更新主张。

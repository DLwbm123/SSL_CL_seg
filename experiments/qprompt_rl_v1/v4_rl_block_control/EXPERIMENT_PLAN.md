# V4：分块 U 权重控制的 RL 实验计划

## 1. 授权、目标与完成标准

用户于 2026-10-03 明确要求设计详细计划并在 GPU 5/6/7 上实验，不做训练时间限制。本计划是新的有限研究矩阵，不续跑已停止的 V3L，也不恢复历史监测。

研究问题：在相同学生、标签、源模型和完整训练日程下，状态相关的 U 权重控制是否改善新域分割与旧域保持；多步 PPO 是否比短期 bandit 和打乱对照更有效。

- 仅使用服务器 `jiangsuiyang` 的物理 GPU 5、6、7，至多一项本研究作业占用一张卡。每次调度前检查可用显存至少 6 GiB；不修改其他进程。
- **不设置 optimizer deadline、hard deadline、超时杀进程或按剩余时间缩短训练。** 训练以固定步数、固定回合及完整矩阵完成为终止条件。无时限不等于无限调参。
- 性能条件只用于最终判读。负结果不停止剩余对照、不改变种子/方法、不自动追加实验。工程错误停止依赖阶段，不自动重试。
- 完成启动交付：计划和源码冻结、工程资格通过、后台队列正常运行、一次启动状态/进程名/GPU检查。无需保持聊天等待实验结束，不创建监测自动化。
- 实际完成后生成全量匿名汇总和报告，按项目规则校验并提交推送 GitHub；数据、病例级评分、模型、特征和原始日志仅留 NAS。后台完成不代表公开交付已验证。

## 2. 固定底座、数据角色和科学边界

复用 `v3b_lrref_endpoint.engine` 的 Trainer/Provider、原生 `source_task`、Adam、投影、数据流、readout、teacher EMA=0.99、固定置信阈值 >0.7 及 soft KL。新增目录承载本研究控制器与调度，不改 V0.1 方程、冻结数据、manifest、split、历史产物或停止回执。

- 学生仍为已使用的 NativeLRParent / LCRSegUNet2DJASCL；原始 KI 历史身份未核实。
- 每个目标域都独立从 REFUGE 源模型开始 stage 1；这是两个局部域迁移任务，不是完整三域顺序 CL，不报告完整 BWT。
- **正式终点使用原生完整日程：RIM_ONE_r3 3200 步、Drishti_GS 2100 步。** Adam、LR/warmup 等跟随原生配置。1200 步仅保留可复查快照，不评分、不用于选择。
- 开发源种子：168/169/170，复用已封存的三份 8000 步源模型，共 24000 次历史源更新单列。它们在历史研发中出现过，不能称新独立种子。
- 确认源种子：173/174/175/176/177，每个重新训练 REFUGE 8000 步，共 40000 次新更新。与开发种子不重叠。
- 开发沿用患者分组的训练 L 内部 fit/online/audit：排序后的前 2 位患者为 online、接下来的 2 位为 audit，其余为 fit。fit 进入学生梯度与状态梯度；online 产生控制器奖励；audit 只作描述性诊断，不选择模型/回合/阈值。三集合不相交，但这些患者此前已用于研发，不能称全历史未见。
- 正式确认使用完整当前域训练 L/U；控制器参数冻结，禁用 online/audit 奖励，不在确认过程中更新策略。
- val 只在一个确认单元的全部方法训练完成后通过独立 evaluator 产生。val 已跨轮用于研发；五个新种子只确认优化随机性，不确认新患者泛化。test 保持封存，U 隐藏标签不读取。冻结 split 不重划。
- 旧域真值与 val 不进入奖励；当前原生参数保护保持不变。因此本轮不声称实现了具有真实旧域反馈的约束 RL。旧域保持是终点判定的必要分量。

## 3. 动作、状态和控制周期

每 25 个学生更新作一次选择，整个 25 步持续同一权重：

`action 0 -> lambda_U=0; action 1 -> lambda_U=0.125; action 2 -> lambda_U=0.5`。

lambda=0 使用原生 L-only 路径，其余使用同一 FINE 三类 soft KL。掩码、分母（所有 valid 像素）、数据流、教师和学生优化均一致。没有本轮类别筛选、粗标签切换、教师速度搜索、新教师或附加损失。

状态沿用 40 维结构：16 维训练进度、LR、类别比例、概率、熵、接纳率、师生差异和监督损失；24 维候选参数更新效果。进度以实际域总步数归一化。候选效果重新对应 lambda 0/.125/.5，而不是旧 SKIP/COARSE/FINE。状态梯度只来自 fit L。每次提取记账 4 次 VJP 和 3 次虚拟 Adam 预演，必须不改变学生、教师、Adam、scheduler、RNG 或读计数。

状态标准化仅由开发面板拟合，常量列置零；z 固定裁剪至 [-10,10]，正式运行同时报告越界比例。网络固定为 40→32→3 的 tanh actor、独立的 40→32→1 critic。无域 ID、病例 ID、验证分数输入。每域分别训练控制器，本研究不主张跨域零样本策略泛化。

总 optimizer 调用为 565556，历史源 24000 单列，不混入新增计数。特征、反馈推理、独立评估、墙钟和显存额外单列。没有工程 replay 预留，也没有自动重试；失败事务保留并停止依赖路径。

三卡使用有限依赖队列：P0通过→源准备与面板并行→P2拟合→P3六项独立学习作业→P4十项 seed/domain 作业。各卡只运行自己的串行作业。中间有两个域的阶段最多用两卡，避免为占满GPU制造额外实验。

### P0：工程资格

1. 合成可学习任务、GAE终止边界、bandit目标、控制器Adam恢复的确定性自检。
2. 两域三档权重的原生 Adam/虚拟更新一致性、单次反向、完整状态快照归属、恢复后相同下一步（既有 `check_native`）。
3. 新40维特征提取前后状态完全相同。
4. lambda=0 与原生 L-only 单步全状态一致。
5. 只使用两份训练L病例进行128步smoke拟合，固定clean质量必须改善；不把这段当性能结果。
6. lambda=.125 的完整25步块两次恢复继续完全一致。

### P1：全时段动作收益面板

每个开发 seed/domain 保留一条全程 FINE_05 轨迹。每50步冻结一次完整状态，分别运行三档权重25步，于第5和25步测量 online/audit 质量。分支结束恢复同一起点，原 retained 轨迹不吸收分支状态。

RIM 每种子64状态，三种子共192；Drishti 每种子42状态，三种子共126。每状态三动作，覆盖完整进度。反馈质量沿用负的类平衡 NLL 加 rim/cup soft-Dice loss，越大越好；不是终点 Dice 百分点。

报告 h5/h25 最优动作一致性、online选动作在audit上的收益、留出开发种子的策略收益。事后最大值仅为有噪声诊断，不解释为可达到的泛化上界。

### P2：固定离线策略

OFFLINE_5、OFFLINE_25 使用相同状态和网络，分别最大化各自窗口的相对 FINE_05 质量增益，加 0.001 KL 到均匀动作先验。每次256步Adam，lr=.003，梯度范数上限1。优势用对应开发窗口的RMS（下限1e-4）缩放。

额外执行 h25 留一开发种子的三个拟合，仅用留出种子audit作描述性诊断；最终两种策略都用全部开发面板重用的固定主拟合，不按OOF/audit结果选模型。标准化及策略写入 OFFLINE_POLICY_LOCK，不能由确认结果更新。

### P3：短期与多步策略的匹配比较

三种方法均从 OFFLINE_25 的同一 actor/critic 状态开始，固定标准化，开发种子168/169/170顺序循环4次，共12回合。每回合重新从对应源模型开始完整目标域日程，不将前一回合学生带入下一回合。

- 每25步奖励为 `(Q_online_after - Q_online_before) / frozen_scale`。scale为开发面板25步绝对质量增量的RMS，下限1e-4。
- 不剪裁奖励；gamma=1使一回合原始增量之和等于终点质量减入口质量。每回合实际检查该恒等式。
- BANDIT_25：advantage = 当前块奖励 − critic；critic拟合当前块奖励，不传播未来回报。
- PPO_25：gamma=1、GAE lambda=.95、终点bootstrap=0；critic拟合lambda-return。
- REWARD_SHUFFLE：与PPO完全相同，但在完整回合内用固定随机种子打乱奖励与时间/状态的对应，保留回合奖励多重集。它是破坏时序信用分配的对照，不等同于所有奖励信息被清空。
- 每回合结束4次全批更新，Adam lr=.0003，PPO clip=.2，value coefficient=.5，entropy coefficient=.01，gradient clip=1。优势在该回合内标准化；同一次PPO更新固定behavior log-prob。
- 开发采样策略为0.9×actor softmax + 0.1×均匀分布，保持每个动作至少1/30的探索概率。保存的behavior概率和PPO新概率使用同一混合公式；正式确认用确定性argmax。
- actor/critic、optimizer、动作采样generator、当前trajectory与学生完整状态持久化；源数据流不受控制器采样RNG影响。
- 每回合audit质量只记录，不触发学习率调整/提前停止/回合选择。固定第12回合后的控制器为最终模型。

全部六个最终控制器写入 FINAL_POLICY_LOCK 后才能进入确认，主矩阵控制器更新数必须为0。

### P4：11组完整确认

| 方法 | 定义 | 区分的问题 |
|---|---|---|
| ORIGINAL | 全程lambda=0 | 与原始监督底座比较 |
| FINE_0125 | 全程lambda=.125 | 固定低剂量 |
| FINE_05 | 全程lambda=.5 | 固定高剂量主基线 |
| EARLY_05 | 前半程.5、后半程0 | 简单时间规则 |
| EFFECT_RULE | 候选虚拟更新对fit质量的一阶效果选权重 | 无奖励拟合的简单规则 |
| OFFLINE_5 | 5步收益训练，25步持续动作 | 短奖励窗口 |
| OFFLINE_25 | 25步收益训练，25步持续动作 | 奖励窗口的配对对照 |
| BANDIT_25 | 在线开发、短期奖励信用 | 无未来回报对照 |
| PPO_25 | 在线开发、多步回报 | 预先指定的主候选 |
| REWARD_SHUFFLE | 打乱开发奖励时序的PPO | 信用分配是否有用 |
| PHASE_SHUFFLE | 主PPO动作序列按早中晚分别打乱 | 相同权重次数/阶段剂量，改变状态对应与时序 |

每个 seed/domain 的方法从完全相同的模型/teacher/Adam/scheduler/RNG入口开始。PHASE_SHUFFLE须等该单元PPO轨迹完成后生成，用固定独立RNG在三个按block等分的阶段内排列；逐阶段权重次数完全相同。它不保证梯度范数或反馈效用相同，也不区分阶段内部的时间效应与状态适应。

## 5. 预先固定的统计与成功判据

每病例先取rim/cup宏平均，再按域、种子等权。报告新域Macro Dice、rim、cup、disc union、旧REFUGE Dice及入口变化；旧域入口差不是完整BWT。所有种子、域、失败单元保留。

对每个配对比较，报告五个种子的两域均值差、样本SD、两域分别的均值及全部10个cell，不把10个cell说成10个独立种子，不做事后显著性或等效声明。

通用联合通过条件：新域均值严格为正且达到指定最小值；旧域均值不下降；至少4/5种子新域为正且旧域不下降；两个域分别在新旧指标上均不下降。

- **RL特有贡献**：PPO相对BANDIT与REWARD_SHUFFLE分别达到新域至少+0.2个百分点，并相对PHASE_SHUFFLE、EFFECT_RULE分别通过通用联合条件。
- **实际候选**：PPO相对FINE_05新域至少+0.3个百分点，并相对ORIGINAL、FINE_0125、EARLY_05分别通过通用联合条件。
- 只有两组判断都通过，才能称本轮得到有实际收益且有RL对照支持的候选；任一失败如实报告。其他方法即使更高也不能事后替换主候选，仅作后续假设。
- .2/.3个百分点是本轮预设研发阈值，不是临床意义或统计显著性界限。所有阈值在本轮评分前固定，不因结果修改。

## 6. 存储、进程、检查点与交付

创建全新NAS运行目录。code快照、配置、全部checkpoint、缓存、日志、临时文件和报告都在NAS；启动经过项目 `with_nas_storage.sh`，挂载和实际写读探针失败即拒绝启动，不回退home。容量预算预留至少100 GiB。

主协调器、GPU worker、evaluator都使用环境变量传路径与模块，进程命令行仅出现中性Python入口。启动后检查完整 `ps` 与 `nvidia-smi`。不在命令行放项目、方法或受限制用户名。

源模型沿用原生checkpoint与SEALED receipt；目标学生每100步保留完整最新状态，另存1200步和最终部署模型；控制器保留最新状态与最终冻结文件。发生失败或用户停止后保留状态、成本与错误，不暗中从头重跑或重置预算。

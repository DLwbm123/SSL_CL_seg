五、阶段 B2：跨随机流动作价值诊断
==================================================

不能把“在同一条流选最大值、再在同一条流评估”
当成可靠选择收益。

固定 tie-breaking：
优先 native，之后按既有低 alpha / action ID 顺序。

对每个状态 s=(c,t)，定义：

a_s^(1) = argmax_a R[s,a,1]
a_s^(2) = argmax_a R[s,a,2]

定义全局固定动作：

a_global^(k) = argmax_a mean_s R[s,a,k]

另定义仅依赖进度的固定动作：

a_time^(k,t) = argmax_a mean_c R[c,t,a,k]

分别做两次交叉评价：

- 使用流 1 选动作，在流 2 评价；
- 使用流 2 选动作，在流 1 评价。

评价流中的 uniform 价值为该状态九个动作收益的算术均值，
不要再用一次随机动作抽样增加噪声。

必须报告：

A. 状态相关选择 − uniform；
B. 状态相关选择 − 全局固定动作；
C. 状态相关选择 − 仅依赖进度的固定动作；
D. 全局固定动作 − uniform；
E. 两条流的动作排序相关性、最佳动作一致率；
F. reward 差异中的 gain 与 forget_penalty 分量。

同时列出：
- 两个方向各自的结果；
- 双向平均；
- 8 个情境各自的结果；
- step=100 / 200；
- 支持量 2 / 8。

聚合顺序：
先在情境内部平均两个决策时点，
再对 8 个情境等权平均。

同流 max-reward 只能标为：
“同表事后最优参考”。

不能标为：
- 可部署策略；
- 无偏性能上界；
- 独立泛化性能。

跨流评价只检验这些固定情境下的训练随机性稳定性。

==================================================
十、GRPO 实现与预算归因
==================================================

沿用项目已核验的离散 GRPO 实现：

- 每组 G=4；
- 四个动作从该组冻结的行为策略独立有放回采样；
- 每个分支运行 100 次原生学生更新；
- 每组从同一完整学生入口恢复；
- 使用相同学生随机流进行组内配对；
- 同一组内不得更新行为策略后再采后续动作；
- advantage 使用组内中心化与 population std；
- std < 既有 floor 时按原实现跳过 actor 更新；
- 不因为跳过而补采 group；
- clip epsilon=0.2；
- Adam lr=0.001；
- entropy coefficient=0.01；
- gradient clip=1；
- 每组最多 4 次 actor 更新；
- 行为策略 KL > 0.02 时沿用既有组内早停。

明确记录：
本轮未使用额外冻结参考策略 KL 惩罚。
行为 KL 早停不等于参考策略 KL 正则。
这是项目既有的离散 GRPO 配方，不声称逐项复现语言模型原始训练设置。

每组保留预先指定的 branch 0 推进学生状态。
不得保留奖励最佳分支。

情境顺序、入口恢复和两组一个 H300 episode 的逻辑沿用已有实现。
每个分支只允许：
100→200 或 200→300。

COLD 的 53 组不要求刚好填满最后一轮情境循环。
按预定 group 数停止，报告实际各情境/时点曝光。
不得临时补组“凑整”。

私有动作 RNG 不得消耗学生 RNG。
诊断和 query readout 必须恢复：
模型模式、参数和 buffer、EMA、memory、学生优化器、
scheduler、随机状态、provider/cursor 与曝光记录。

物理计算账本不能随状态恢复回滚。


预算比较分成两类，不能混写：

A. 相同新增 GRPO 分支预算

WARM_GRPO_16 与 COLD_GRPO_16：
每种子 16×4×100 = 6,400 次学生更新。

该比较回答：
相同新增交互预算下，监督热启动是否有帮助。

不能单凭该比较宣称总成本优势。


B. 计入监督信息生成的两种子联合预算

监督热启动需要的额外准备：
- native step=200 状态生成：800 次学生更新；
- 完整动作收益生成：28,800 次学生更新；

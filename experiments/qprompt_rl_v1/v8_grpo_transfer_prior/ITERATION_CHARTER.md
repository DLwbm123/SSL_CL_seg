# 长期实验与每小时监测

授权来源：用户于 2026-10-06 明确要求“设置长期运行的实验，然后每小时监测，如果效果还不好的话，分析原因，并继续提升并继续实验”。

## 执行方式

每小时自动唤醒当前对话，读取实际服务器状态；训练使用可靠后台队列。自动化已启用，不等于训练已经启动。当前仍等待患者身份依据或明确接受图像级探索修订；这项尚未决的研究口径选择不因定时器启用而自动通过。

## 逐轮改进

- 每轮先登记假设、一个主要改动、匹配对照、有限矩阵、预算、成功/失败门槛，再运行。
- 原 V8 的阶段停止保持其原含义；新授权允许封存失败并研究下一轮，不追改该轮的失败定义。
- 优先查实现资格、奖励波动与动作差异、实际梯度及有效监督量、保持代价、训练部署一致性。若证据不支持某一方向，淘汰该方向，不用追加种子寻找正结果。
- 原生、固定策略、随机策略的匹配对照仍须保留；按域、种子、结构分项、旧域绝对遗忘及相对保持同时报告。
- 每轮最多沿用原 V8 的学生 255,160 次、actor 960 次总上限，实际新轮应登记更小的定向预算；不得转移分类额度或把未使用额度用于补跑。跨轮累计账本持续递增，不能重新归零。
- history-free、A-only、可用标签和 sealed test 边界持续有效。不得用已离开域的真实标签更新控制器。
- 一个阶段的训练全部结束后统一评估；禁止根据中间验证曲线选 checkpoint、挑最佳候选学生或修改门槛。
- 技术修复先保留失败入口与耗费，在新修订身份下重新通过必要资格检查。不得越过 ExecutionPermit 或其他科学权限。

## 资源与交付

仅使用原授权服务器和 GPU 5/6/7；启动前确认显存、NAS 挂载与真实写读探针，不干扰其他作业。使用 create-only NAS 目录、既有存储包装器和中性可见进程命令。

每小时检查实际成功步数、主路径/分支账本、最新日志、进程和错误。仅在有阶段结果、实质进展、失败、需要用户动作或交付完成时通知；不重复播报未变化阻断。

每个完成或停止的轮次发布源码、配置、匿名完整结果与分析，并通过代理验证 GitHub 远端提交和公开报告。私有数据与模型留在 NAS。

当前自动化复用已有 `v3b-lrref` 记录，已更新名称与提示词，未创建重复计划。用户要求停止时保留 checkpoint、证据和累计账本，并停止自动化。
